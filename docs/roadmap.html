Roadmap

Where HHT is, and where it might go. Each item carries a status. Only Available items exist in the app today. Apart from the App Store target below, there are no dates: a planned item is an intention, not a promise.

Available in the app today In progress being worked on now Planned intended, not built Exploratory an idea, no commitment

Progress is tracked in GitHub issues and released versions are listed in the changelog.

Phase 1 · Personal diary, stabilised Available

  • Background collection with motion-aware GPS and battery-saving stationary mode. Available
  • Deterministic reconstruction of visits, trips, mode segments and named places. Available
  • Corrections (mode, place, purpose, times, split, merge, delete) locked against rebuilds, with an audit log. Available
  • One-tap self-reported stamps for stops too short to detect. Available
  • Stats, Home Screen widgets, flights, life phases, period comparisons. Available
  • Export to CSV, JSON, GeoJSON and SQLite, plus a Python loader. Available
  • Calibration harness and regression fixtures for known failure modes (#46). Available
  • Accessibility audits for the app and the docs. Available

Phase 2 · Public iOS release In progress

The same personal diary, installable from the App Store instead of being built with Xcode. The target is around 10 November 2026. It depends on App Review and may move.

  • App Store packaging, review and privacy disclosures that match the Privacy page. In progress
  • Documentation that separates current features from future plans (this page). In progress

Version 1.0 on the App Store does not add the research features in the phases below.

Phase 3 · Granular, voluntary export Planned

Today an export covers everything or the last 30 days, and always includes a full database snapshot (see what an export contains). This phase would let a user share less.

  • Choose specific dates or trips to export. Planned
  • Choose the level of detail: aggregates only, trips without routes, or full traces. Planned
  • Make the SQLite snapshot follow the same selection, or leave it out. Planned
  • A preview of exactly what will leave the phone before sharing. Planned

Phase 4 · Research-oriented recall and study configuration Planned

  • Prompted recall: end-of-day questions about trips the app is unsure of (mode, purpose, companions). Planned
  • A study configuration file: which questions to ask, which fields to export, study ID. Planned
  • Built-in consent text and an explicit hand-over step to the researcher. Planned
  • Keeping the engine's original output when a record is first edited, so accuracy can be measured from real use. Planned

Phase 5 · Validation and data standards Planned

  • A formal, multi-participant accuracy benchmark with published protocol and results. Planned
  • Shareable, reproducible GPS test fixtures (synthetic or consented and de-identified). Planned
  • A battery and completeness benchmark across devices. Planned
  • A versioned, machine-readable export schema, and mapping to common HHTS codebooks. Planned
  • Transit-aware mode detection (for example GTFS) to separate bus from car. Exploratory

What is measured today is on the Validation page.

Phase 6 · Broader infrastructure Exploratory

  • An Android version. Exploratory
  • Offline-first data hand-over for places with poor connectivity. Exploratory
  • A multilingual interface. Exploratory
  • Optional, self-hosted collection for studies that run their own server. Exploratory

Any feature that sends data off the device would be opt-in, documented on the Privacy page, and discussed publicly before it is built.

How to influence the roadmap

Open a feature request, or comment on an existing issue with your use case. Concrete research needs ("I need trip purpose for 20 volunteers over two weeks") are the most useful input. See Contributing.
