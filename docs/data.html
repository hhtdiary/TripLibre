Concepts

Data model & export

Everything TripLibre knows is in one SQLite file. The export bundle is that same data as CSV, JSON and GeoJSON, with stable IDs that join across every table.

Conventions

FieldConvention
*_tsUTC Unix seconds (REAL). Exports add a matching *_utc ISO string.
tzIANA time zone of the device when recorded. Local dates and hours use each record's own tz, so travel across zones stays correct.
CoordinatesWGS84 decimal degrees
DistancesMetres, great-circle (haversine, R = 6 371 008.8 m)
IDsLowercase UUID strings for visits, trips, places…; integers for raw points
route_polylineGoogle encoded polyline, precision 1e-5, simplified with Douglas–Peucker (8 m)
DeletesSoft: deleted = 1. audit_log keeps every old → new value.

The database is at Library/Application Support/HHT/travel.sqlite (WAL mode). The schema version is in PRAGMA user_version; migrations are append-only.

The final mode of a trip is COALESCE(mode_user, mode_auto, 'unknown'). The full column-by-column reference is in docs/data-model.md.

Views

  • v_trips: non-deleted trips plus mode_final, purpose_final, duration_s, and final origin/destination places.
  • v_visits: non-deleted visits plus place name, category and duration_s.

Analysing in Python

cd analysis
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python explore.py ~/Downloads/hht-export-20260927-120000
from hht import load, summary, mode_share

d = load("~/Downloads/hht-export-20260927-120000")  # export folder, or a travel.sqlite file
d.trips.head()                       # one row per trip
summary(d.phase("Fall 2026"))        # trips/day, km/day, radius of gyration, entropy…
mode_share(d.trips, by="distance_m") # or "trips", "travel_time_min"

Analysing with SQL

Open travel.sqlite in DuckDB, R (DBI), QGIS or the sqlite3 CLI and use the views:

-- mode share by trips for the last 30 days
SELECT mode_final, COUNT(*) AS trips, ROUND(SUM(distance_m) / 1000, 1) AS km
FROM v_trips
WHERE departure_ts >= strftime('%s', 'now', '-30 days')
GROUP BY mode_final
ORDER BY trips DESC;
✓

audit_log is a ready-made labelled dataset: every set_mode row is a ground-truth mode for a trip, which is useful for evaluating or training a better mode classifier.

Metric definitions

MetricDefinition
Person-dayLocal date with ≥ 1 trip or visit. Per-day rates divide by person-days, not calendar days.
Mode shareBy trips, distance or time, on the final mode; also by group (active / car / transit / long-distance / other).
Radius of gyration√(Σ wᵢ d(pᵢ, c)² / Σ wᵢ) over visited places, dwell- and visit-weighted.
Activity spaceConvex hull area of visited places.
Destination / mode entropyShannon entropy (bits) of visits per place / trips per mode.
Time away from home24 h − time at home places, over days with a home visit.
Home-based tourTrips from leaving home to next arriving home; complex tour = ≥ 2 stops.
Repeat OD shareShare of trips whose origin→destination pair already occurred earlier in the period.
