Contributing

Bug reports, fixes and new features are welcome. HHT is small enough to read in an afternoon, and most of the interesting logic lives in a package you can test without a phone.

Development setup

git clone https://github.com/zyang91/HHT-app.git
cd HHT-app
brew install xcodegen
make test     # core tests, no simulator needed
make sim      # run the app with demo data
make lint     # docs JS/CSS/HTML + accessibility, Markdown, Python (needs node + ruff)

Changing the docs site? Run npm run lint (or npm run lint:fix) before opening a PR. The HTML check includes html-validate's accessibility rules: images need alt, buttons need a type and an accessible name, and aria-label only goes on elements that can carry one.

Where to make a change

You want to…Look in
Improve visit / trip / mode detectionInference/ and InferenceConfig; add a fixture scenario in Tests/HHTCoreTests/InferenceTests.swift
Add a correctionEditing/EditService.swift; always write audit_log and set user_status
Change the schemaDatabase/Schema.swift; add a new migration, never edit an old one
Add a metricAnalytics/MobilityMetrics.swift, mirrored in analysis/hht.py and docs/analytics.md
Add an export columnExport/Exporter.swift; the Python contract check (make export-check) must still pass
Change background collectionApp/Location/LocationCollector.swift; test on a real device, the simulator can't reproduce it
Change a Home Screen widgetViews in Widgets/; data in Widget/WidgetSnapshot.swift (bump currentVersion if its shape changes, and extend WidgetSnapshotTests)
Change the UIApp/Screens/, styling in App/Support/Theme.swift
Edit these docsdocs/*.html; navigation is in docs/assets/docs.js

Ground rules

  • Never modify raw observations. raw_location_points and motion_activities are append-only.
  • Never overwrite user corrections. Anything with user_status ≠ auto is locked against inference.
  • Keep inference deterministic. Same input → same output, and incremental runs must equal one-shot runs.
  • No new network calls without discussion. Anything that sends data off the device must be opt-in and documented on the Privacy page.
  • No third-party dependencies in HHTCore.
  • Thresholds go in InferenceConfig, not inline.

Before opening a pull request

  1. Run the checks CI runs 
    make ci
  2. Regenerate the project if you touched project.yml: make project, and commit HHT.xcodeproj. CI fails if they differ.
  3. Update docs: the markdown specs in docs/*.md and these pages if behaviour changed.
  4. Open the PR against main with a short description of what changed and why.

Reporting issues

Use the issue templates for bugs and feature requests. For a wrong trip or visit, describe what happened and what HHT recorded. Don't attach raw exports: they contain your location history. Security problems go through SECURITY.md, not public issues.

Everyone participating is expected to follow the Code of Conduct.
